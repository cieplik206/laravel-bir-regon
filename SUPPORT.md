# Support policy

Laravel BIR REGON was created for and is used in the maintainer's own
projects. It is published as open source in case it is useful to other Laravel
developers.

## Maintenance model

The package is maintained on a best-effort basis. It does not include
commercial support, a service-level agreement, a guaranteed response time, or
a commitment to implement feature, compatibility, or integration requests.
Opening an issue does not guarantee that it will receive a response, a fix, or
a release within any particular timeframe.

The supported-version table in [SECURITY.md](SECURITY.md) describes which
versions are eligible for security fixes. It does not create a customer-support
commitment or an SLA.

## Getting help

Before opening an issue, review the [documentation](README.md#documentation)
and search the existing issue tracker. Reproducible bug reports and focused
pull requests are welcome, but their review and acceptance remain subject to
the maintainer's availability and the needs of the package.

Do not use a public issue for a suspected vulnerability. Follow the private
reporting process in [SECURITY.md](SECURITY.md), and never include a production
BIR API key or other credentials.

## Responsibility

Users are responsible for evaluating whether the package and data returned by
GUS are suitable for their own application, legal, security, and operational
requirements. The GUS service, its availability, and its data are outside the
maintainer's control.
